| # | Area | Finding | Severity |
|---|------|---------|----------|
| F1 | Save / 409 | On `stale_revision` the user must manually reload; the draft is kept but `revision` isn't auto-refreshed. Works, but the recovery step is manual. | UX-low |

## 4. What breaks most often (fragility notes)

1. **Export-wrapper / version detection** — the v1.5 import bug came from
   `migrateAndSanitize` checking the version before unwrapping the `{ data }`
   envelope. Any future change to the export shape or `detectVersion` must keep
   "unwrap first, then detect" — there's now a regression test guarding it.
2. **Environment setup, not code** — the most common real failure is a missing
   `DATABASE_URL` / `SESSION_SECRET` or un-run `db:setup`, surfacing as the
   "No connection to the server" screen. This is operational, not a bug.
   Preview deploys specifically lack `SESSION_SECRET` (Production-only).
3. **Mobile CSS overrides** — admin/operator layouts rely on `!important`
   media-query overrides with specificity battles (e.g. `grid-column: auto`
   clobbering spans). UI tweaks here are easy to get subtly wrong; verify on a
   real narrow viewport after each change.
4. **Optimistic concurrency** — concurrent admin edits hit 409 and require a
   manual reload+reapply; no auto-merge.

## 5. v1.6 vs v2.0 triage

### v1.6 (small, safe, incremental)
- Fix F2 copy (recovery toast).
- Document the operational setup gotcha (DATABASE_URL / SESSION_SECRET /
  db:setup, Preview vs Production secrets) — see §6.
- Optional: prune expired `login_attempts` rows on a schedule (F5).
- Optional: smoother 409 recovery — auto-refetch the latest revision and
  re-present the draft so the user can re-save without a manual reload (F1).

### v2.0 (larger, architectural)
- Move cover/drawing images to dedicated blob storage (shrinks catalog JSON,
  removes the size caps as a practical limit) — F6.
- Self-service password rotation or external identity provider (retires D4).
- Real stale-save merge/reapply flow instead of reload-and-retry.
- Branch protection / required checks / secret push-protection on `main`
  (GitHub-UI setup; D11 residual).
